User Manual

How to use this library

From a first attention call to a full continuous-batching serving loop with a quantized paged KV cache — three callables, one descriptor.

flash-attention-cuda  ·  consumer Blackwell (sm_120), tuned on RTX 5080  ·  fp16 / bf16 · D = 64 / 128 · MHA / GQA / MQA

This is the practical manual. The entire feature set — batched and ragged prefill, split-KV decode, paged KV caches with FP8/INT4 quantization, cache writes, chunked multi-turn prefill — is reachable through fa_attention, fa_cache_attention, and fa_cache_write, configured by plain structs. For the field-by-field reference see api-guide.md; for how the kernels work and how fast they are, see the README and vllm-comparison.md.

1Build and link

mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . --target flash_attention   # the static library
cmake --build . --target flash_bench       # optional benchmark suite

Requirements: CUDA 12.0+ (13.x tested), CMake 3.20+, compute capability 8.0+. For fastest builds pin your GPU in CMakeLists.txt (set(CMAKE_CUDA_ARCHITECTURES "120") for an RTX 5080). Integration is one header and one library:

target_link_libraries(your_app PRIVATE flash_attention)
// #include "flash_attention.h" — everything is in namespace transformer

2The mental model

CallableUse it for
fa_attentionattention over tensors you hold (prompts, training-style batches)
fa_cache_attentionattention against a paged KV cache — decode and chunked prefill, routed by query length
fa_cache_writeappending new K/V into the cache (quantizes automatically)
KvCache (struct)all state of one cache: pools, block table, lengths, geometry, quantization

Conventions that apply everywhere:

  • fp16/bf16 chosen by the DType dtype field; pointers are typed half* as address carriers either way.
  • GQA/MQA via num_kv_heads (0 = MHA); d_head ∈ {64, 128}; scale = 0 means 1/√d_head.
  • All index arrays (cu_seqlens_*, block_table, seq_lens, slot_mapping) are device memory.
  • Zero-initialize every args struct — the defaults are all valid. Bad arguments abort with a named message instead of corrupting memory.

3Recipe: plain batched attention

FaAttentionArgs a = {};
a.Q = q; a.K = k; a.V = v; a.O = o;   // device half*, [B,H,S,D]
a.batch_size = 8;
a.num_heads  = 32;
a.num_kv_heads = 8;                    // GQA 4:1 (0 = MHA)
a.seq_len = 4096;
a.d_head  = 128;
a.causal  = true;
a.autotune = true;                     // optional per-shape tile search (wisdom-cached)
fa_attention(a);

The dispatcher picks the kernel tier by GPU saturation automatically; autotune benchmarks the candidate tiles once for this exact shape and remembers the winner across runs.

4Recipe: ragged prompts (varlen)

Pack unequal-length sequences with no padding: Q/O become [total_q, H, D] — exactly what a QKV projection produces, so no transpose — with device prefix sums:

// lens = {512, 300, 1000}  →  cu_q = {0, 512, 812, 1812}
FaAttentionArgs a = {};
a.Q = q_packed; a.K = k_packed; a.V = v_packed; a.O = o_packed;
a.cu_seqlens_q = cu_q;                 // switches to varlen mode
a.cu_seqlens_k = cu_k;
a.batch_size = 3; a.num_heads = 32; a.num_kv_heads = 8;
a.max_seqlen_q = 1000; a.d_head = 128; a.causal = true;
fa_attention(a);
Causal masking in varlen mode is bottom-right aligned: query i attends kv j ≤ i + (seqlen_k − seqlen_q). Passing a longer seqlen_k therefore is chunked/append prefill — new tokens attending an existing prefix plus themselves.

5Recipe: the serving loop

Step 0 — allocate the cache. Payload pools are [num_pages, page_size, H_kv, D] elements of the cache dtype (AUTO: 2 B/elem · FP8: 1 · INT4: 0.5 plus scale pools):

KvCache cache = {};
cache.K = k_pool; cache.V = v_pool;
cache.block_table = block_table;       // [B, max_blocks_per_seq], device
cache.seq_lens = seq_lens;             // [B], device
cache.max_blocks_per_seq = max_blocks;
cache.page_size = 16;
cache.num_kv_heads = 8; cache.d_head = 128;
cache.max_seq_len_kv = 32768;          // host-known upper bound
cache.kv_dtype = KvDType::FP8_E4M3;    // see §6
cache.k_scale = k_max/448.f; cache.v_scale = v_max/448.f;

Step 1 — prompt attention, then fill the cache.

fa_attention(varlen_prompt_args);      // §4: prompts, no cache yet

FaCacheWriteArgs w = {};
w.K_new = k_packed; w.V_new = v_packed; // [total_tokens, H_kv, D]
w.slot_mapping = slots;                 // [total_tokens]: page*ps + slot
w.num_tokens = total_tokens; w.cache = cache;
fa_cache_write(w);                      // quantizes per cache.kv_dtype

Step 2 — the decode loop. One query token per sequence; Q is [B, H_q, D]:

FaCacheAttentionArgs d = {};
d.Q = q_step; d.O = o_step; d.cache = cache;
d.batch_size = B; d.num_heads = 32;
d.max_seqlen_q = 1;                    // → decode path (split-KV)
size_t sb = fa_cache_attention_scratch_bytes(d);
cudaMalloc(&d.scratch, sb);            // allocate once, reuse every step

for (;;) {
  fa_cache_attention(d);
  /* model computes next token + its K/V ... */
  fa_cache_write(step_w);              // append 1 token per sequence
  /* scheduler bumps seq_lens, grows block tables, admits/evicts */
}

Step 3 — multi-turn follow-up (chunked prefill). Write the new tokens' K/V into the cache first, then run the chunk against the whole cache:

fa_cache_write(chunk_w);               // new K/V → pages FIRST

FaCacheAttentionArgs p = {};
p.Q = chunk_q; p.O = chunk_o; p.cache = cache;
p.cu_seqlens_q = cu_chunk;
p.max_seqlen_q = max_chunk_len;        // > 1 → chunked-prefill path
p.batch_size = B; p.num_heads = 32; p.causal = true;
fa_cache_attention(p);
Chunked prefill currently requires an AUTO (fp16/bf16) cache; FP8/INT4 caches are decode-only for now.

6Choosing a KV-cache dtype

kv_dtypeKV memoryDecode speed
(D=128, long ctx)		Accuracy cost
(worst case)		Scales
AUTO1×baseline (~99% HBM peak)——
FP8_E4M31/2~1.8× faster~0.035 nrmseyou provide per-tensor k_scale/v_scale (max|X|/448)
INT4_G32~1/4~1.2–1.8× faster~0.10 nrmsecomputed automatically per 32-channel group (allocate K_scales/V_scales)

Rule of thumb: FP8 for speed, INT4 for capacity. The accuracy costs are gaussian-random worst cases; calibrated real-model KV does better, and both formats add zero kernel error on top of the quantization itself.

7Validate and benchmark

Seven independent gates validate everything against double-precision references under a strict policy (random std=1 inputs, thresholds ~4× the noise floor). Run them after any change; each exits 0 on pass:

fa_validate · fa_varlen_validate · fa_paged_validate · fa_fp8_validate
fa_int4_validate · fa_paged_prefill_validate · fa_api_validate

flash_bench reports per-shape TFLOPS through the production dispatcher.

abort: INT4_G32 … requires K_scales/V_scalesscale pools not allocated/attached

9Python bindings — the handles

The same surface is available from Python as the fa_ptx package (pip install -e python/, or import fa_ptx from the repo for a JIT build). All tensors are CUDA fp16/bf16; index tensors are CUDA int32. The ops are torch.compile- and CUDA-graph-compatible.

fa_ptx.attention(...) → Tensor

fa_ptx.attention(q, k, v, *,
    cu_seqlens_q=None,   # None → batch mode; set → varlen mode
    cu_seqlens_k=None,   # required in varlen mode
    max_seqlen_q=0,      # varlen: longest query segment
    num_kv_heads=0,      # 0 = MHA; else GQA/MQA
    causal=True,
    scale=0.0,           # 0 = 1/sqrt(d_head)
    autotune=False)      # batch mode only

Batch mode: q/k/v are [B,H,S,D]. Varlen mode: q packed [total_q, H_q, D], k/v packed [total_k, H_kv, D]; causal is bottom-right aligned. Returns O shaped like q.

fa_ptx.PagedKVCache

cache = fa_ptx.PagedKVCache.allocate(
    num_pages=..., page_size=16, num_kv_heads=8, d_head=128,
    batch_size=B, max_seq_len_kv=32768,
    kv_dtype="auto",          # "auto" (fp16/bf16) | "fp8" | "int4"
    k_scale=0.0, v_scale=0.0, # required > 0 for "fp8"
    dtype=torch.float16, device="cuda")

Or wrap existing pools by constructing the dataclass directly (k_pool/v_pool, block_table [B, max_blocks], seq_lens [B], plus the geometry fields). The caller mutates block_table, seq_lens, and pool contents in place as sequences grow — that is the supported pattern.

cache.write(k_new, v_new, slot_mapping)
#   k_new/v_new : [num_tokens, H_kv, D]      (quantized per cache.kv_dtype)
#   slot_mapping: [num_tokens] int32, page_id*page_size + slot; < 0 skips

o = cache.attend(q, *,
    cu_seqlens_q=None,   # None / max_seqlen_q == 1 → decode
    max_seqlen_q=1,      # > 1 → chunked prefill ("auto" caches only)
    causal=True, scale=0.0,
    num_splits=0)        # decode split-KV; 0 = auto
#   decode: q is [B, H_q, D]; prefill: q packed [total_q, H_q, D]

Decode scratch is managed by the object automatically. For custom integration the raw operators are exposed as torch.ops.fa_ptx.attention, .cache_attention, .cache_write, and .cache_scratch_bytes — the wrappers above are thin conveniences over them.
